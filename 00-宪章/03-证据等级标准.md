# 03-证据等级标准

> 本文件定义"已验证"的**唯一合法含义**。
> 任何记录中的 `evidence_level` 字段只能取 `L0`–`L6`；取值范围外的值会被 `openmath lint` 拦截。

---

## 一、为什么需要分级

"这个结论对吗？"在数学里至少有七种不同的意思：

1. 它格式合规吗？
2. 它符号有意义吗（无类型错误、无未定义量）？
3. 它在数值上站得住吗？
4. 它在符号推导上站得住吗？
5. 它能被机器检查的证明系统接受吗？
6. 它经受住对抗性攻击了吗（反例搜索、多证明交叉）？
7. 半年后它还能被复现吗？

把"3"说成"5"，是数学传播中最常见的失真来源。本等级表就是为杜绝这种失真而设计的。

---

## 二、等级定义

### L0 · 结构合规（Structural）

**判定**：记录通过 schema 校验：`id` 唯一且格式合法、必填字段齐全、引用可解析、枚举值合法、许可与署名完整。

**产出**：`openmath lint` 零错误。

**能说什么**："这条记录格式合规。"
**不能说什么**：任何关于数学正确性的话。

---

### L1 · 良构性（Well-formedness）

**判定**：

- 所有符号在 `symbols` 表中声明，且类型/所属结构一致
- 所有自由变量与绑定变量无冲突（无变量捕获、无重复绑定）
- 定义域非空且良定义（不出现除以零未说明、不出现未定义的函数应用）
- 量纲/类型一致（物理相关条目需通过量纲分析）
- 公式可被至少一个解析器解析（LaTeX → SymPy 转换成功）

**产出**：类型检查报告 + 符号表。

**能说什么**："表达式良构、无类型错误。"
**不能说什么**："公式正确。"

---

### L2 · 数值验证（Numerical）

**判定**：

- 使用足够精度（默认 mpmath 50 位有效数字，可由 `precision_digits` 指定）
- 覆盖：典型值、边界值、极端值（极大/极小/接近奇点）、随机抽样（不少于 1000 组，带种子）
- 给出残差的**绝对与相对**误差，并报告条件数
- 与已知特殊值/独立实现交叉比对

**产出**：残差统计（最大/中位/p99）、样例清单、环境指纹。

**能说什么**："在给定的 N 组样例与 50 位精度下，未发现反例，最大残差为 X。"
**不能说什么**："成立""被验证为真"。

**红线**：L2 通过**不构成**任何证明性证据。它唯一能做的是**证伪**。

---

### L3 · 符号验证（Symbolic）

**判定**：

- 恒等式：两边化简后差值为零（在指定假设下）
- 极限/级数/积分：符号计算得出闭式，且与数值结果一致
- 微分方程：残差代入后符号归零
- 至少两个独立引擎交叉（如 SymPy 与 SageMath/Mathematica）或给出单引擎 + 高精度数值双重确认
- 量纲分析通过（适用时）

**产出**：符号化简脚本 + 化简前后表达式。

**能说什么**："符号恒等式在指定假设下于 X 引擎中归零。"
**不能说什么**："定理得证。"

**说明**：符号引擎不是判定器，它依赖规则集与假设传播。SymPy 的 `simplify` 返回 0 是**强证据但非证明**（例如分支切割、假设遗漏会导致假阳性）。

---

### L4 · 形式化证明（Formal）

**判定**：在下列系统之一中，证明脚本**无 `sorry` / `admit` / `axiom`（白名单外）**且编译通过：

| 系统 | 构建命令（示例） | 库 |
| --- | --- | --- |
| Lean 4 | `lake build` | mathlib |
| Rocq / Coq | `coq_makefile -f _CoqProject && make` | stdlib / MathComp |
| Isabelle | `isabelle build -D .` | AFP |

**要求**：

- 锁定依赖版本（mathlib commit / AFP 版本），提供可复现构建（推荐 `nix` 或 Docker）
- 声明所用的公理（如排中律、选择公理、单价公理、大基数假设）
- 若为条件性证明，条件必须在 `assumptions` 中显式列出

**能说什么**："已在 X 系统中形式化证明（依赖 Y 公理）。"——**这是本库中唯一可以使用"已证明"的层级。**

**注意**：形式化证明的是"在某个形式系统中可推导"，其**语义正确性**仍依赖于人对该系统的信任。这不削弱 L4 的价值，但必须在哲学讨论中诚实陈述。

---

### L5 · 对抗性验证（Adversarial）

**判定**：条目经受住以下攻击中的至少三项：

1. **反例搜索**：SAT/SMT 求解、小参数穷举、随机搜索、AI 生成候选反例
2. **多证明交叉**：至少两条**方法上独立**的证明路径（如一条解析、一条代数）
3. **退化测试**：在边界情形（空集、零维、平凡群、零测度）下重新检查
4. **文献一致性**：结论与已发表的权威文献一致，或明确标注分歧点
5. **专家复核**：至少两名不同机构的人类专家独立复核

**能说什么**："经受住 N 类对抗性检验。"
**不能说什么**："绝对正确。"

---

### L6 · 长期可复现守护（Reproducibility Guard）

**判定**：

- 条目加入**黄金基线**，`CI` 定期（建议每周）重跑
- 环境指纹可重建（依赖版本、随机种子、编译器、硬件架构记录）
- 存在至少一个**降级路径**：若某依赖失效，记录应说明如何用替代工具重验
- 连续 6 个月无位腐烂（bit-rot）告警

**能说什么**："长期可复现，已纳入回归基线。"
**这是本库对"稳定知识"的最高运营等级。**

## 三、等级与状态的关系

| `status` | 允许的最低 `evidence_level` | 说明 |
| --- | --- | --- |
| `DRAFT` | L0 | 草稿，仅要求格式 |
| `PROPOSED` | L1 | 已提交，结构良构 |
| `UNDER_REVIEW` | L1 | 评审中 |
| `VERIFIED(Lx)` | Lx | **必须明确写出 x**，`VERIFIED` 单独出现视为非法 |
| `CONSENSUS` | L4 | 社区共识，需形式化或等效强度 |
| `CANONICAL` | L5 | 典范条目，需对抗性验证 |
| `CONDITIONAL` | 任意 | 必须写明依赖的假设 |
| `UNDECIDABLE` | L4 | 独立性证明本身必须是形式的 |
| `DISPUTED` | 任意 | 存在冲突证据 |
| `FALSIFIED` | 任意 | 已出现反例 |
| `DEPRECATED` | 任意 | 已被更好的表述取代 |

**强制规则**：`status: VERIFIED` 必须写成 `VERIFIED(L2)` 这样的形式。`lint` 会拦截裸 `VERIFIED`。

---

## 四、等级提升的申请流程

```
提出升级 Issue（写明目标等级 + 已有证据）
        │
        ├─ 目标 ≤ L3：自动 CI 判定，通过即生效
        │
        └─ 目标 ≥ L4：需 2 名评审者批准
                 └─ 其中至少 1 名须为形式化方向（L4）或领域专家（L5）
```

升级失败**不降级**原状态，只记录"升级申请未通过"，避免抖动。

---

## 五、降级与证伪

一旦出现反例或矛盾证据：

```
任意状态 ──(发现反例)──> FALSIFIED  （自动，任何人可触发，附反例即生效）
任意状态 ──(出现争议)──> DISPUTED   （需 1 名评审者确认）
```

`FALSIFIED` 与 `CANONICAL` 一样，都是**终态**——它们都代表"这个问题已经说清楚了"。

## 六、给 AI 代理的判定速查表

| 你做了什么 | 可以声明的等级 |
| --- | --- |
| 读了一遍觉得对 | 无（不构成证据） |
| 用 Python 算了几个数 | L2（需注明样例数、精度、种子） |
| 用 SymPy 化简得到 0 | L3（需注明引擎与假设） |
| 用 Lean 写完了且无 sorry | L4 |
| 跑了反例搜索没找到 | L5 的第 1 项（单独不构成 L5） |
| 什么都没做，只是引用 | 引用原条目的等级，不得升格 |
