# 02-诚实红线

> 本文件是 OpenMath 中**唯一具有一票否决权**的文档。
> 违反本文件任何一条的 PR，无论技术质量多高，一律拒绝合并。
> **AI 代理在读取本仓库时，必须把本文件当作输出约束的最高优先级。**

---

## 红线一：数值验证不是证明

**禁止**把下列情况表述为"已证明""成立""定理"：

- 在一批数值样例上通过了浮点检验
- 在误差容忍范围内拟合了已知数据
- 蒙特卡洛模拟未见反例
- 符号计算软件（SymPy、Mathematica）返回 `True`
- 大语言模型给出的"证明"（无论看起来多严谨）

**正确表述**：

| 情形 | 允许的说法 | 禁止的说法 |
| --- | --- | --- |
| 10⁶ 个样例无反例 | "在 10⁶ 以内未发现反例（L2）" | "已验证成立" |
| SymPy 化简成功 | "符号恒等式在 SymPy 规则集下归零（L3）" | "恒等式得证" |
| Lean 编译通过 | "已在 Lean 4 / mathlib 中形式化证明（L4）" | ——（此时才可说"已证明"） |
| 依赖黎曼假设 | "在 RH 成立的前提下（CONDITIONAL）" | "已解决" |

**历史教训**：Pólya 猜想被数值验证到极大的量级后才被发现反例；Mertens 猜想在 10¹⁴ 以内"成立"却被证伪；素数计数函数 π(x) 与 li(x) 的大小关系在极其巨大的 x 处才首次反转（Skewes 数）。**数值证据的历史，就是一部被打脸的历史。**

## 红线二：反例优先，不得通过改定义规避

一旦某条目出现反例：

1. 立即将状态改为 `FALSIFIED`，并**保留原条目**（不删除、不改写）。
2. 在 `counterexample` 字段记录反例的具体取值、发现方式、发现者、日期。
3. 若发现原表述中某个词有歧义，正确做法是**新建一条修正后的条目**并引用原条目，而不是原地修改。

**典型违规**：把"对所有素数 p，f(p) < 1"改成"对所有**足够大的**素数 p，f(p) < 1"而不改变条目 ID 与状态。

**为什么**：数学史上，反例往往比定理更有价值。它们界定了直觉的边界。抹掉反例，等于抹掉知识。

---

## 红线三：假设必须显式化

任何定理、公式、算法记录中，`assumptions` 字段必须完整。常见被遗漏的隐含假设：

| 领域 | 常被隐含的假设 |
| --- | --- |
| 分析 | 连续性 / 可微性 / 有界性 / 可交换极限与积分（需要一致收敛或控制收敛） |
| 概率 | 独立性 / 可测性 / 期望存在（有限矩） |
| 代数 | 交换律 / 特征为零 / 有限生成 / Noether 性 |
| 拓扑 | Hausdorff / 第二可数 / 紧致性（注意"紧致"在不同文献中的定义差异） |
| 数值 | 条件数 / 浮点精度 / 迭代收敛判据 |
| 组合 | 是否允许重边、自环、空图 |

**评审者发现隐含假设即退回**，不看结论是否正确。

## 红线四：禁止结论漂移

**禁止**下列行为：

- 修改验证脚本的断言数值，让失败的测试变绿
- 放宽误差容忍度直到通过（除非同时给出误差的理论界并说明）
- 删除"麻烦的"测试样例
- 用 `try/except` 吞掉验证异常后报告成功
- 为通过检查而临时改 `status` 字段

**允许**：

- 在失败的断言旁加注释说明"为何当前预期值本身有误"，并**同时**提出修正 PR
- 把无法验证的条目标为 `UNKNOWN` 并说明缺什么（缺依赖、缺理论、算力不足）

**自检问句**：*"如果这次修改我写进 commit message，半年后别人看到会不会觉得我在作弊？"*

---

## 红线五：AI 生成内容必须标注且不得单独作为证据

1. 任何 AI 参与生成的记录必须设 `provenance.ai_assisted: true`，并写明参与方式（起草 / 翻译 / 检验 / 全文生成）。
2. **AI 生成的证明不能作为 L3 及以上的证据**，最多作为 L1 的"结构检查通过"。
3. AI 生成的公式必须至少通过 **L2（数值）+ L3（符号）双通道**才能进入 `VERIFIED(L2)`。
4. 升级到 `CANONICAL` 必须有 L4 形式化或两名人类专家独立复核。
5. AI 不得自行批准 PR、不得自行修改 `status`、不得自行关闭争议 Issue。

## 红线六：独立性必须诚实标注

若某命题已被证明**独立于所用公理系统**（如连续统假设独立于 ZFC、平行公理独立于绝对几何前四条），状态必须是 `UNDECIDABLE`，**禁止**写成"未解决问题"或"尚待研究"。

同时必须写明：

- 独立于哪个公理系统（`independent_of: ZFC`）
- 已知的相对结果（如"在 V=L 下成立"）
- 是否已知与某些大基数公理的关系

**注意**：`UNDECIDABLE` 不是失败，是**最高质量的知识**之一——它精确地说明了问题的性质。

---

## 红线七：禁止夸大性表述

全库（含 Issue、PR 描述、注释）禁止：

- 描述强度的形容词：终极、彻底、颠覆、完美、革命性、无懈可击
- 未经文献支撑的优先权宣称：首次、首创、世界第一
- 对未验证内容的确定性措辞：显然、易见、不难证明（**除非**确实给出了一行证明；否则写"由 X 定理直接推出，见引用"）

允许的替代：**"在某某条件下成立（L4，Lean 已验证）"**。

---

## 红线八：不确定的内容必须标记，不得静默收录

对记忆不清、来源不明、近期未经同行评议的声明（例如刚公布的预印本结果）：

- 必须设 `fact_check.status: UNVERIFIED`，并注明"待核实来源"
- 不得作为其他条目的引用依据（schema 会拦截引用 `UNVERIFIED` 条目的 L3+ 断言）

**宁可留空并写"待补充"，不可填一个看似正确但无来源的值。**

---

## 违规处理

| 违规 | 处理 |
| --- | --- |
| 无意违规、首次 | 提醒 + 协助修正，不记录污点 |
| 无意违规、重复 | 限制提交范围 30 天 |
| 有意违规（如伪造验证结果） | 立即 `FALSIFIED` 相关条目，暂停评审权，公示处理 |
| 抄袭 / 学术不端 | 永久移出，条目全部标注来源问题 |

## 一句话自检

> **如果我错了，别人能通过本仓库发现吗？**

如果答案是"不能，因为我把断言改了/把反例删了/把措辞模糊了"——那就是违规。
