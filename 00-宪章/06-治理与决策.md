# 06-治理与决策

## 一、治理原则

> **用规则替代权威，用证据替代资历，用留痕替代记忆。**

OpenMath 不设"首席数学家"。所有决策走可追溯的流程，任何决定都能回答"谁、依据什么、什么时候、为什么"。

## 二、角色

| 角色 | 产生方式 | 权限 | 任期 |
| --- | --- | --- | --- |
| **贡献者 Contributor** | 提交 PR 即获得 | 提交、评论、自评 | 永久 |
| **评审者 Reviewer** | 在某一域累计 5 个被合并的 `VERIFIED(L3+)` 条目 | 批准该域的 L0–L3 升级 | 12 个月，可续 |
| **领域负责人 Domain Lead** | 由该域现有评审者推荐 + 治理组确认 | 分支目录结构与该域标准 | 18 个月 |
| **形式化组 Formalization Group** | 提交过 L4 条目 | 批准 L4/L5 升级 | 12 个月 |
| **治理组 Governance** | 5 人，每年轮换 2 名 | 宪章解释、争议终裁、行为准则执行 | 12 个月 |

**回避规则**：任何人不得批准自己参与起草的条目的等级升级。

## 三、决策矩阵

| 事项 | 决策方式 | 门槛 |
| --- | --- | --- |
| 普通 PR 合并 | 任一相关域评审者批准 | 1 人 |
| L4 / L5 升级 | 形式化组 / 领域负责人 | 2 人（其中 1 名形式化组） |
| 新增域代码 | 领域负责人 | 1 人 + 公示 7 天 |
| 新增验证层级 | 治理组 | 3 人 + 公示 14 天 |
| 新增统一纲领 | 治理组 | 3 人 + 公示 14 天 + 必须填写可证伪预测 |
| 宪章修改 | 见宪章第六条 | 3 人 + 公示 14 天 |
| 行为准则处理 | 治理组 | 简单多数 |
| 条目删除 | **不存在此流程** | 只能 `DEPRECATED` / 归档 |

## 四、争议裁决流程

```
1. 争议提出（Issue 打 `dispute` 标签，写明冲突的两条证据）
        │
2. 事实层澄清（7 天）
   └─ 双方各自列出：所用假设、证据等级、可复现产物
        │
3. 判别（按优先级顺序，命中即止）
   ├─ a. 一方证据等级严格更高 → 高等级方胜（除非高级证据本身被指出缺陷）
   ├─ b. 等级相同 → 看是否有反例：有反例者胜（证伪优先）
   ├─ c. 都无反例 → 看是否可复现：不可复现方负
   ├─ d. 都可复现 → 看假设强弱：假设更弱者胜（奥卡姆）
   └─ e. 仍无法判别 → 双方条目同时标 `DISPUTED`，等待新证据
        │
4. 记录（裁决书写入 07-社区/03-会议与日志/，并链接到相关条目）
```

**关键**：第 3 步的 e 分支是合法结局。**"目前无法判定"是一个有效的知识状态**，强行裁决才是失职。

## 五、AI 代理在治理中的地位

| 允许 | 禁止 |
| --- | --- |
| 生成候选证明/反例并标注 `ai_assisted` | 自行批准 PR |
| 执行 L0–L3 自动验证 | 自行提升 `evidence_level` 到 L4+ |
| 提出争议（打 `dispute` 标签） | 关闭争议 Issue |
| 维护索引与看板 | 修改宪章 |
| 标注可疑条目（打 `needs-review`） | 删除条目 |

**AI 的投票权为零，但其提出的可复现反例具有完整效力**——因为反例是证据，不是意见。

## 六、透明性要求

1. 所有决策必须在 `07-社区/03-会议与日志/` 留下记录，含日期、参与人、依据、结论。
2. 治理组讨论摘要每月公开一次（涉隐私的行为准则事件除外）。
3. 每个季度公布一次指标：新增条目数、各证据等级分布、被证伪条目数、未决争议数。
4. **被证伪条目数上升不视为负面指标**——它是验证在起作用的证据。

## 七、资金与中立性

- 项目不接受附带内容审核权的资助。
- 任何机构资助必须在 README 与 `07-社区/` 中公示。
- 不接受与 [宪章第三条](../00-宪章/01-宪章总纲.md#第三条--四条基本原则) 冲突的商业合作（例如要求隐藏某条目的 `FALSIFIED` 状态）。

## 八、紧急流程

出现下列情况时，治理组可启动紧急流程（48 小时内处置，事后补公示）：

- 发现某 `CANONICAL` 条目存在根本性错误且被广泛引用
- 发现伪造的验证结果
- 安全事件（如依赖投毒）

紧急处置后必须在 7 天内补齐完整记录，并做一次流程复盘写入日志。
