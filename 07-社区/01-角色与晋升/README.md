# 01-角色与晋升

> **晋升看证据，不看活跃度。**

## 一、为什么用"证据"而非"活跃度"

常见的开源晋升标准（提交数、Issue 数）会激励**灌水**：提交大量低质量内容以换取头衔。

本库用**证据等级**作为标准：晋升需要提交**被验证过**的内容。

## 二、路径

### ① 路人（Passerby）

- 读 README 与红线
- 无需注册

### ② 贡献者（Contributor）

**获得方式**：提交第一个 PR（无论是否被合并）

**权限**：提交、评论

### ③ 评审者（Reviewer）

**获得方式**（需同时满足）：

- 在**某个域**累计 5 个被合并的条目
- 其中至少 3 个达到 `VERIFIED(L3+)`
- 无 [红线](../00-宪章/02-诚实红线.md)违规记录

**权限**：批准该域的 L0–L3 升级

**任期**：12 个月，可续（续期需过去一年有 ≥2 次评审）

### ④ 领域负责人（Domain Lead）

**获得方式**：

- 已是该域评审者
- 由该域现有评审者推荐
- 治理组确认

**权限**：该域的目录结构、标准制定

**任期**：18 个月

### ⑤ 形式化组（Formalization Group）

**获得方式**：提交过至少 1 个 L4 条目

**权限**：批准 L4/L5 升级

### ⑥ 治理组（Governance）

**获得方式**：5 人制，每年轮换 2 名

**权限**：宪章解释、争议终裁、行为准则执行

## 三、为什么门槛这样设

| 门槛 | 理由 |
| --- | --- |
| "某一域" 而非"全库" | 数学高度专业化；没有人能评审所有域 |
| "被验证过" 而非"提交过" | 防止灌水 |
| 形式化组单独设 | L4 需要专门技能，与数学能力不同 |
| 任期制 | 防止凝固；也避免长期负担 |

## 四、降级机制

| 情形 | 处理 |
| --- | --- |
| 任期到期不续 | 自动降为贡献者 |
| 长期不活跃（>6 个月） | 权限暂停（可恢复） |
| 红线违规（重复） | 限制提交范围 |
| 伪造验证结果 | 立即剥夺所有权限 |

**降级不是惩罚**，是资源的重新配置。权限意味着责任，不承担责任的权限应当收回。

## 五、回避规则

> **任何人不得批准自己参与起草的条目的等级升级。**

这适用于所有层级。若某域只有一名评审者，则升级需由治理组指定跨域评审者。
