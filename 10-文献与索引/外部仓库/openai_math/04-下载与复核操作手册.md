## 二、四个已经踩过的坑（每个都有对应的"判据"）

**① 同名覆盖。** 用 `basename` 把 `/README.md` 与 `/lean/README.md` 落到同一目录，后者静默吃掉前者。
> 判据：**把 API 声明的字节数与盘上字节并读**。发现方式不是读内容，是 650 B ≠ 4,190 B。

**② 网络写盘"成功"不等于能解析。** Trees API `?recursive=1` 写出 4,845,568 B 后截断，
**`curl` 返回 0**，直到 `json.load` 才炸（`Unterminated string`）。
> 判据：**能否被解析**，不是退出码；`| tee` 还会吞掉退出码。
>
> **2026-10-11 复测（读数由 `scratch/RT_probe_face.txt` 印出，全表在 `_镜像/PROVENANCE.md` §二②b）**：
> 那份"看着写全了"的 5,767,159 B 响应（工作树已删，只在 openmath 的 git 历史里）逐字节量得
> **4,183,058 B = 72.53% 是一段连写的 NUL**，空洞从第 38,733 行开始、之后接在一条 URL 的**中间**；
> 全文件 `"path"` 键 **4,982** 条，而 `git ls-tree` 报 **133,955** 条（覆盖 **3.72%**，缺 **128,973** 条），
> 且 `"truncated"` 字段**一次都没写进来**，文件结尾停在半条 URL 上、不以 `}` 结束。
> ⇒ 判据再加一条：**尺寸像成功是最危险的一型**——它不报错，只给出一份看似完整的清点。
> 物理层清点因此只认 `git ls-tree --name-only`（`_生成/stats.txt` H 段）。
> 判据再补一条，是本轮自己交的学费：写这份判据时，Python 字面量里少打一层反斜杠（`\x00` 只写了 `\x00` 的前一半），于是把**一枚真 NUL** 写进了台账，由 `count(b"\x00")` 读数=1 抓出并修掉。⇒ **文档写完要做 NUL 普查**，不只 JSON 才要做；该读数现在由生成器的 I6 行常设（`_生成/stats.txt`）。

**③ `-l` 在 blobless clone 上是陷阱。** `git ls-tree -r -l` 要 blob 尺寸 ⇒ 逐对象按需取回，
2 分钟不返回被手动终止；同一仓库 `--name-only` 瞬间出全 133,955 行。
> 判据：`.git` 从 4.4 MB 涨到 5.1 MB 就是"确已取回过对象"的读数（涨了什么**未清点**）。

**④ `sparse-checkout set` 是**替换**语义。** 新 pattern 列表会把上一轮物化的目录**从工作树删掉**。
> 判据：换 pattern 后 `ls preprints/` 只剩新列表里的目录。要同时保留就多写 pattern，别指望追加。

## 三、C 档实操：命令与实测耗时

```bash
# 建一个"只到清单层"的本地仓库（B 档到此为止）
git clone --filter=blob:none --no-checkout --depth 1 https://github.com/openai/math.git repo
git -C repo -c core.quotepath=false ls-tree -r --name-only HEAD | gzip -9 > git_paths.txt.gz

# C 档：要哪几个目录就列哪几个 pattern（一次列全，见坑④）
git -C repo sparse-checkout set --no-cone \
  '/preprints/<目录名>/**' '/lean/ComparatorChallenges/*.json'
git -C repo checkout HEAD
```

耗时读数（PROVENANCE §三，同一 `.git` 上顺序做的）：

| 动作 | 实测 |
| --- | --- |
| 416 份 `ComparatorChallenges/*.json` | **3.175 s**，`du -sk` = 565；此后 `.git` = **25,270 KB / 65 pack** |
| 家族 007 的整个目录 | `set` **20.488 s**；**21 个文件** / `du -sk` 1,133 |
| 家族 013 的整个目录 | **21.280 s**；**14 个文件** / `du -sk` 1,053 |
| 撤回第 1 件的目录 | **3.844 s**；2 个文件（README 1,385 B + 1 页通告 PDF） |
| 撤回第 2、3 件（换 pattern） | **2.299 s**；4 个文件，**上一轮目录同时消失** |
| 撤回三件一次列全再取 | **1.002 s**（对象已在本地 ⇒ 只重写工作树） |

**读法**：耗时由"该目录有多大"和"对象是否已在 `.git` 里"两件事决定，不由目录个数决定
（同样 3 个目录：首次 3.8 s + 2.3 s，第二次一次取回 1.0 s）。

## 四、正文文件名**不许猜**（本库实测的两类拼写陷阱）

1. **PDF 文件名不统一**：H 段现数 `.pdf` 共 **776** 份、不同 basename **201** 种
   （`paper.pdf` **440**、`main.pdf` **96**、`manuscript.pdf` **20**、`article.pdf` **16**、`sectors.pdf` 2……），
   而 `dirs holding paper.pdf` 只有 **440**／**749** 个目录；撤回件里三份分别叫
   `paper.pdf` / `manuscript.pdf` / `hodge-conjecture-products-k3.pdf`。
   ⇒ 任何"正文一定叫 paper.pdf"的脚本会在 **309** 个目录上取空（749−440，H 段两个数相减）。
2. **目录名与标题不同形**：标题里都写 `CAT(0)`，目录名却有 `CAT(0)`、`CAT0`、`CAT-0` 三种
   （家族 337／257／254）。全仓含字面 `(` 的路径只有 **15** 条，全在 337 那一个目录下，`lean/` 下 **0** 条（H/I5 段）。
   ⇒ 定位文件只许走 `_生成/manuscripts.csv`（家族号 → 路径 → 行号），不许从标题拼路径。

每篇稿件目录自带的 `README.md` 里有**可引用的 BibTeX 键**，形如
`OAI:<目录名>`（例：`OAI:the-additive-indecomposability-of-the-primes-September-24-2026`），
`author = {{OpenAI}}`，`year = {2026}`——引用具体稿件时用它，别自己编号。
