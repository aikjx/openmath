## 一、形式化层有四本账，它们互不相等（B 段）

| 口径 | 数 | 是什么 |
| --- | --- | --- |
| CONTENTS 家族行内引用 `lean/docs/NNN.md` | **242** | 被标记"有形式化"的**家族**数 |
| 盘上 `lean/docs/*.md` | **242** | 与上一行**双向闭合**：引用而缺 0，缺而未被引 0（H 段） |
| `formalization.yaml` 的 `sources:` | **172** | 论文级条目数（172/172 都指向 `../preprints/…pdf`） |
| `formalization.yaml` 的 `status.main_results` | **200** 条声明／**189** 个不同 config／**192** 个不同 `.lean` | "主结果"声明数（一条 config 可含多条声明） |
| 盘上 `ComparatorChallenges/*.json` | **416** | 全部**可检声明**（主结果 + 支撑结果） |

四个数不是"同一件事的四舍五入"，而是**四个不同对象**：家族、论文、主结果声明、全部声明。
`by_subject.csv` 用第 1 行口径，`comparator_axioms.csv` 用第 5 行口径；引用时必须点名用了哪一行。

## 二、"~42% 已形式化"在本库复现不出来（B 段）

上游 `history.md`（2026-10-07 条目）逐字写着：**"300 / 719 = ~42%"**，
`README.md` 又把它表述成"~42% **top-line results** formalized"。

B 段把这四个候选分子都算了一遍：

```
families flagged with a lean doc      : 242
lean/docs/*.md referenced             : 242
formalization.yaml sources            : 172
formalization.yaml main_results decls : 200
manuscripts inside flagged families   : 475
equality 300 == manuscripts-in-flagged-families ? False
```

- **没有一个等于 300。** 在目录层与元数据层，300 这个分子**不可定位**。
- 单位也对不上：`top-line results` 若指家族，分母应是 **372** 而不是 719；
  若指稿件，"top-line"这个说法就名不副实。
- 本库能给出的三条**可复现**率（`_生成/stats.txt` B 段的 rates 块，三条逐字抄自该块；不点行号——该文件由脚本重生成，行号会挪）：
  - 家族口径 **242 / 372 = 0.6505**（该家族有没有形式化标记）
  - 稿件口径 **475 / 719 = 0.6606**（把被标记家族内的全部稿件算作已形式化，**上界读法**）
  - 保守读法 **242 / 719 = 0.3366**（标记数除以稿件数）
  ⇒ 上游自报的 `300 / 719`（`_镜像/history.md` 第 31 行原文 `300 / 719 = ~42%`；0.4172 是本库现除的结果，
    不由任何载体印出）落在本库区间 **[0.3366, 0.6606]** 之内，所以它**并不荒谬**，
  只是在本库镜像的层上**无法核对**。
- **本库表述纪律**：只许写"上游自报 ~42%；本库在目录层复现不出该数，可复现的是
  该块印出的 242/372、242/719、475/719 三种口径"。**不许**把 42% 抄进本库任何统计表当自己的读数。

## 三、声明级公理普查：这一层比 README 更硬（I 段）

416 份 config 全部落在同一 pin 上抓取（`_镜像/comparator_json/`），逐条读出的事实：

| 检查 | 读数 | 含义 |
| --- | --- | --- |
| `permitted_axioms` 并集 | **3 个**：`propext`、`Quot.sound`、`Classical.choice`，各 **416/416** | 全库声明只允许 mathlib 标准三公理 ⇒ **没有自定义公理、没有 `sorry` 后门** |
| 允许非标准公理的 config | **0** | 同上 |
| `permitted_axioms` 为空的 config | **0** | 没有"忘了声明"的条目 |
| `theorem_names` 总声明数 | **537**（416 份 config） | 一份 config 可检多条定理 |
| `theorem_names` 为空的 config | **1**：`ElementaryPositivity` | 它检的是 `definition_names`（一个 witness），**不是定理** ⇒ 该条不构成"某定理已形式化" |
| 同时带 `definition_names` 的 config | **10** | 名称一致性检查，与定理证明是两类判据 |
| `enable_nanoda = true` | **2**：`ArtinParabolicIntersections`、`TraceIdealTransportSupport` | 开启内核 `decide` 归约 ⇒ 信任面从"类型检查"扩到"大数值求值"，**本库要单列** |
| 缺 `enable_nanoda` 字段 | **2**（414/416 有该字段） | 缺失时本库**不推断默认值**，只报"字段缺席" |
| `solution_module` 能在盘上定位 | **416 / 416** | 每条声明都有对应 `.lean` 源文件 |

**结论**：在"**声明—公理—源文件**"三元关系上，上游是**自洽且可核**的，这比 README 那句
"~42%"强得多；真正缺的是下一节的两样东西。

## 四、映射到本库 L0–L6（判据见 `00-宪章/03-证据等级标准.md`）

| 上游层 | 本库等级 | 已满足 | 未满足 |
| --- | --- | --- | --- |
| `CONTENTS.md` / `overview.tex` 目录 | **L0** | schema 与号闭合由本库解析器实测（A 段：372/372 双向无孤立项） | —— |
| 稿件正文（PDF/tex，本库未取） | **未入级** | —— | 本库未做 L1 良构判定，未做 L2 数值复算 ⇒ 只能记"外部主张" |
| `lean/OAI/**.lean` + 416 声明 + `lean-toolchain` + `lake-manifest.json` | **L4 候选** | 版本锁 PRESENT（H 段），其内容已镜像为 `_镜像/lean_probe/lean-toolchain`（25 B，逐字 `leanprover/lean4:v4.34.1`）；公理白名单声明且全库仅标准三公理（I 段）；声明↔源文件可定位 | ①**本库未复跑 `lake build` + `comparator`**（L4 的判定动作本身）；②无 nix／Docker（H 段四项 0）；③**`review: status: unchecked`**（`formalization.yaml` 第 1777–1778 行逐字） |
| `history.md` 的撤回—修复—再引用链条 | **L5 的一部分** | "文献一致性/分歧标注"这一项有实装：1 处符号错误 ⇒ 3 篇撤回 + 14 修订 + 13 引用更新，且**旧版本仍在盘上**（01 号文档 §三） | 反例搜索、两条独立证明路径、边界退化测试、**两名外部人类专家复核**——元数据层均无声明 |
| `reasoning_traces/`（10 份 PDF + 1 份 tex，H 段） | **L0** | 它是**过程摘要**，可作线索 | 不构成任何数学层级证据；本库禁止把它当"证明思路已验证" |

一句话：**上游最高到"可检声明 + 无自定义公理"，本库最高只能给它记 `PROPOSED` + `L4-CANDIDATE`，
在本地复跑成功并有具名人类复核之前，禁止出现"已证明"字样。**
（本库自己的记录是 L4 条目数 = 0；引入外部候选不改变这一读数。）
