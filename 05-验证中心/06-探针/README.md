# 06-探针

> **探针是验证中心的"攻击方"。**
> 它的任务不是确认，而是**尽力推翻**。

## 一、为什么证伪优先

Popper 的洞见在本库中是工程纪律而非哲学：

- 确认的成本高、收益低（再多正例也不能证明）
- 证伪的成本低、收益高（一个反例就能推翻）

因此本目录的工具设计目标是**最大化发现反例的概率**。

## 二、探针类型

| 探针 | 适用 | 方法 |
| --- | --- | --- |
| **穷举探针** | 有限对象（小图、小群、小数） | 遍历全部 ≤ N 的候选 |
| **随机探针** | 连续/大空间 | 随机采样 + 种子记录 |
| **边界探针** | 含边界条件的命题 | 极值、奇点、退化情形 |
| **SAT/SMT 探针** | 可编码为约束满足 | 编码后调用求解器 |
| **对抗探针** | 任意命题 | AI 生成"最可能成为反例"的候选 |
| **数值探针** | 解析命题 | 高精度 + 密集扫描 |
| **交叉探针** | 已有证明 | 寻找第二条独立路径，比对结论 |

## 三、工作流程

```
目标条目（CONJECTURE，形如 ∀x ∈ S: P(x)）
    │
    ├─ 1. 确定搜索空间 S 的可枚举/可采样部分
    │
    ├─ 2. 生成候选（穷举 / 随机 / AI 建议）
    │
    ├─ 3. 逐个检验 P(x)
    │
    ├─ 4a. 找到 ¬P(x) ──> 【反例！】
    │         ├─ 高精度确认（≥ 50 位）
    │         ├─ 独立方法交叉验证（防引擎 bug）
    │         ├─ 写入 03-结果/ + 08-已证伪与反例库/
    │         └─ 目标条目 status := FALSIFIED（终态）
    │
    └─ 4b. 未找到 ──> 记录【搜索上界】
                      "在 |S| ≤ 10^6 的 X 类对象上未发现反例"
                      ⚠️ 不升级证据等级
```

**关键纪律**：4b 分支**绝不**写"验证通过"。它写"搜索了多大范围，没找到"。

## 四、反例的确认标准

发现疑似反例后，**必须**通过：

| 步骤 | 目的 |
| --- | --- |
| 高精度复算（≥ 50 位） | 排除浮点误差 |
| 独立方法/独立实现 | 排除引擎 bug |
| 手工/符号验证（若可行） | 排除编码错误 |
| 同行复核（L5） | 排除理解错误 |

**历史教训**：Mertens 猜想的"反例"需要格基约化（LLL）才能找到；Pólya 猜想的反例在 10⁹ 之后。**"看起来没有反例"和"没有反例"之间有巨大的鸿沟。**

## 五、搜索上界的记录

```yaml
probe_result:
  target_id: OM-C-GT-0007
  probe: exhaustive
  searched:
    space: "n ≤ 12 的全部非同构简单图"
    count: 11005127
    method: "geng (nauty) 生成 + 性质检验"
  found_counterexample: false
  duration_hours: 3.2
  note: "未发现反例。这不构成对该猜想的证据。"
```

**必须包含 `note` 字段**，写明"未发现反例不构成证据"。

## 六、AI 在探针中的角色

| 角色 | 合法性 |
| --- | --- |
| 生成候选反例 | ✅ 合法且高效 |
| 编码为 SAT/SMT | ✅ 合法 |
| 判断"是否为反例" | ⚠️ 需独立验证（AI 判断不可单独采信） |
| 宣称"验证了猜想" | ❌ 禁止 |
| 因"没找到"而升级证据等级 | ❌ 禁止（[红线一](../../00-宪章/02-诚实红线.md)） |
