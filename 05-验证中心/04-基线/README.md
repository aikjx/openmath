# 04-基线

> **黄金基线 = 本库承诺"这些结果必须永远成立"的集合。**
> 基线的唯一目的是**对抗位腐烂（bit-rot）与时间**。

## 一、为什么需要基线

验证结果会随时间失效：

| 失效原因 | 例子 |
| --- | --- |
| 依赖升级 | SymPy 版本更新改变化简行为 |
| 库被弃用 | 某引擎停止维护 |
| 环境变化 | 操作系统、架构变化导致浮点差异 |
| 记录被误改 | 内容漂移未被发现 |
| 构建失败 | mathlib 更新导致 Lean 代码不编译 |

**基线的作用**：定期重跑，第一时间发现这些失效。

## 二、基线的内容

### 2.1 内部黄金基线

从本库条目中挑选的稳定条目，需满足：

- 证据等级 ≥ L3
- 结果稳定（连续 3 次运行结果一致）
- 依赖稳定（不依赖即将弃用的库）
- **必须包含"已知失败"的条目**（验证引擎能正确报告失败）

**最后一条极其重要**：一个只含"应该通过"的基线，无法检测"引擎是否只会说 YES"。必须包含**已知应失败**的样例作为**阴性对照**。

### 2.2 阴性对照集（Negative Controls）

| 类型 | 例子 | 期望结果 |
| --- | --- | --- |
| 已知错误的恒等式 | 如 \(\sin^2 x + \cos^2 x = 1.1\) | L2 `FAIL` |
| 已知被证伪的猜想 | Pólya 猜想 | L2 在反例处 `FAIL` |
| 缺假设的定理 | 交换极限与积分（无一致收敛） | L1 告警 |
| 依赖 AC 但误写为不依赖 | | L1 退回 |

**若阴性对照通过了，说明引擎坏了**——这是最重要的告警。

### 2.3 外部基线（引用，不复制）

| 来源 | 用途 | 许可 |
| --- | --- | --- |
| miniF2F | 形式化基准 | 需核查 |
| ProofNet | 自动形式化基准 | 需核查 |
| MATH / GSM8K | 数学能力基准（**注意饱和**） | 需核查 |
| OEIS | 序列值对照 | 需核查 |

**政策**：只引用，不镜像。引用时记录**访问日期**与**版本**。

## 三、回归检测

```
重跑基线
   │
   ├─ 结果从 PASS 变 FAIL ──> 【回归】高优先级告警
   │
   ├─ 结果从 FAIL 变 PASS ──> 【意外修复】需核查（可能是引擎变了）
   │
   ├─ 残差数量级变化 ──────> 【精度漂移】中优先级
   │
   ├─ SKIP 变 PASS/FAIL ───> 【依赖变化】需更新记录
   │
   └─ 阴性对照通过 ────────> 【引擎失效】最高优先级告警
```

## 四、运行策略

| 场景 | 频率 | 范围 |
| --- | --- | --- |
| CI（每次 PR） | 每次 | 受影响的条目 + 阴性对照 |
| 每日 | 每日 | L0–L3 全量 |
| 每周 | 每周 | 含 L4（构建慢） |
| 每月 | 每月 | 全量 + 环境重建检查（L6） |

## 五、基线文件格式

```yaml
baseline:
  version: "2026.09"
  created: 2026-09-10
  entries:
    - id: OM-F-AN-0001
      level: L2
      expected_status: PASS
      expected_max_residual: "1.0e-45"
    - id: OM-F-AN-0002
      level: L2
      expected_status: PASS
      expected_max_residual: "1.0e-45"
  negative_controls:
    - id: OM-X-TEST-0001        # 已知错误的恒等式
      level: L2
      expected_status: FAIL
      reason: "阴性对照：验证引擎能否正确报告失败"
```

**本库自评**：**阴性对照集的缺失是当前验证中心最大的功能性缺口。** 没有阴性对照，我们无法判断验证引擎是否真的在工作。这是下一个里程碑的首要任务。
