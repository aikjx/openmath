# 03-结果

> 验证产物的**唯一存放地**。所有结果可复现、可追溯。

## 一、目录结构

```
03-结果/
├── README.md
├── 2026/
│   ├── 09/
│   │   ├── OM-F-AN-0002-L2-20260910.json
│   │   ├── OM-F-AN-0002-L3-20260910.json

    ├── by-id/               # 按条目索引
    └── by-level/            # 按层级索引
```

**分片规则**：按**年月**分片，避免单目录文件过多。

## 二、文件命名

```
<条目ID>-<层级>-<YYYYMMDD>[-<序号>].json
```

示例：`OM-F-AN-0002-L2-20260910.json`

同一天多次运行加序号：`...-L2-20260910-2.json`

## 四、保留策略

| 结果类型 | 保留期 |
| --- | --- |
| 最新结果 | 永久 |
| 历史结果 | 12 个月（之后移入 `12-归档/`） |
| `FAIL` 结果 | **永久保留**（这是最重要的结果） |
| 反例 | **永久保留**，并在对应条目中引用 |
| 大产物（>10 MB） | 只存哈希 + 摘要，原文放外部存储 |

**核心原则**：**失败结果比成功结果更有价值，保留优先级更高。**

## 五、结果的使用

| 用途 | 方式 |
| --- | --- |
| 升级条目证据等级 | 引用结果文件路径（见记录的 `verification.levels.Lx.script` / `result`） |
| 回归对比 | 与 [04-基线](../04-基线/README.md) 比对 |
| 看板统计 | [05-看板](../05-看板/README.md) 聚合 |
| 争议裁决 | 结果文件是**证据**，可直接引用 |
| 审计 | 任何人可追问"这个结论是怎么来的" |

## 六、禁止事项

- ❌ 手工编辑结果文件（应重跑验证）
- ❌ 删除 `FAIL` 结果
- ❌ 只记录"通过"而不记录残差值
- ❌ 用结果文件代替条目的证据等级声明（二者需一致）
