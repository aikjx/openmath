# 05-验证中心

> **OpenMath 的心脏。** 前面四个目录负责"有什么"，本目录负责"凭什么相信"。

## 一、设计目标

| 目标 | 含义 |
| --- | --- |
| **分级** | 从格式检查到形式化证明，七个层级，强度单调递增 |
| **可证伪优先** | 验证的唯一高价值产出是**反例**，不是"通过" |
| **插件化** | 新引擎注册即生效，不改核心代码 |
| **可复现** | 每个结果带环境指纹，可在一台干净机器上重跑 |
| **无限扩展** | 层级、引擎、证据类型都可增长 |

## 二、七层协议（速览）

| 层 | 名称 | 回答 | 强度 |
| --- | --- | --- | --- |
| **L0** | 结构合规 | 格式对吗？ | 无数学意义 |
| **L1** | 良构性 | 符号有意义吗？ | 排除类型错误 |
| **L2** | 数值验证 | 数值上站得住吗？ | **只能证伪** |
| **L3** | 符号验证 | 符号推导站得住吗？ | 强证据，非证明 |
| **L4** | 形式化 | 机器能检查证明吗？ | **唯一可称"已证明"** |
| **L5** | 对抗性 | 经受住攻击了吗？ | 多元交叉 |
| **L6** | 守护 | 半年后还能重跑吗？ | 运营级稳定 |

**完整定义**：见 [00-宪章/03-证据等级标准](../00-宪章/03-证据等级标准.md) 与 [00-验证协议](00-验证协议/README.md)。

**一句话**：**L0–L3 用于筛掉错误，L4 用于确认真理，L5 用于对抗自欺，L6 用于对抗时间。**

## 四、插件化架构（"无限扩展"如何落地）

```
                    ┌─────────────────┐
                    │  验证运行时      │
                    │  (scheduler)    │
                    └────────┬────────┘
                             │ 按 capability 派发
        ┌────────────────────┼────────────────────┐
        ▼                    ▼                    ▼
   ┌─────────┐          ┌─────────┐          ┌─────────┐
   │引擎 A   │          │引擎 B    │          │引擎 C    │
   │mpmath   │          │sympy    │          │lean4    │
   │L2       │          │L3       │          │L4       │
   └─────────┘          └─────────┘          └─────────┘
        ▲                    ▲                    ▲
        └──────── 引擎注册表（engines.yaml）──────┘
                    新增引擎 = 加一个条目
```

**新增一个引擎的三步**：

1. 写 `08-工具/openmath/engines/<name>.py`，实现 `run(record, level) -> Result`
2. 在 `05-验证中心/01-引擎/engines.yaml` 注册（声明能力：支持哪些层、哪些域、依赖）
3. 提交自检样例（一个已知通过、一个已知失败）

**核心代码不需要任何改动。** 这就是"无限扩展"的技术保证。

## 五、验证的执行流程

```
记录（OM-*-XXXX.yaml）
    │
    ├─ L0：schema + ID + 引用完整性    ← 纯标准库，永远可跑
    │
    ├─ L1：符号表 + 类型 + 量纲        ← 纯标准库 + 可选 sympy
    │
    ├─ L2：高精度数值                   ← 需要 mpmath
    │      精度、边界、随机、条件数
    │
    ├─ L3：符号化简                     ← 需要 sympy
    │      多引擎交叉
    │
    ├─ L4：形式化                       ← 需要 lean/rocq/isabelle
    │      白名单公理检查
    │
    ├─ L5：反例搜索 + 多证明交叉        ← 可选 SAT/SMT
    │
    └─ L6：定期回归 + 环境重建
```

**降级策略**：某层依赖缺失时，结果标 `SKIP` 而非 `FAIL`，并在看板中显示"覆盖率"。**绝不把"没跑"伪装成"通过"**。

## 六、核心纪律（三条）

### 1. 失败不是坏事

验证失败是**有价值的信息**，应当被记录、被分析、被归档。修改断言让它变绿是 [红线四](../00-宪章/02-诚实红线.md)。

### 2. 反例优先于通过

L5 的探针即使什么都没找到，也要记录**搜索上界**（"在 n ≤ 12 的全部图中未找到反例"）——这是有价值的信息，但**不升级证据等级**。

### 3. 环境指纹不可省略

每个结果必须记录：

```
依赖版本 / 随机种子 / 精度位数 / 操作系统 / 架构 / 时间戳
```

缺失环境指纹的验证结果，最高只能算 L1。

## 七、当前能力（诚实）

| 层级 | 状态 | 说明 |
| --- | --- | --- |
| L0 | ✅ 已实现 | `openmath lint`（纯标准库） |
| L1 | ⚠️ 部分 | 符号表检查已实现；量纲检查仅框架 |
| L2 | ✅ 已实现 | `openmath verify --level L2`（需 mpmath） |
| L3 | ✅ 已实现 | 需 sympy |
| L4 | ⬜ 未实现 | 目录与规范已建，绑定待开发 |
| L5 | ⬜ 未实现 | 探针规范已建 |
| L6 | ⬜ 未实现 | 基线结构已建 |

**我们不掩饰**：验证中心的**规范**先于**实现**落地，这是有意的——先定标准，再写工具，避免工具绑架标准。
