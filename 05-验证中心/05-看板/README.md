# 05-看板

> 把验证状态变成**一眼可读**的指标。看板的设计原则：**暴露问题，而非粉饰成绩**。

## 一、生成方式

```bash
python -m openmath status                  # 终端输出
python -m openmath status --format json    # 机器可读
python -m openmath status --write          # 写入 03-难题与猜想/10-状态看板.md
python -m openmath status --check          # CI 模式：有回归则退出码非 0
```

## 二、核心指标

### 2.1 覆盖度指标

| 指标 | 说明 |
| --- | --- |
| 条目总数 | 按类型（D/F/T/C/X/A） |
| 各证据等级条目数 | L0–L6 分布 |
| **验证覆盖率** | 跑过 L2+ 的条目 / 总条目 |
| **SKIP 率** | 因依赖缺失未跑的比例（**必须显示**，不得隐藏） |

### 2.2 质量指标

| 指标 | 说明 | 期望 |
| --- | --- | --- |
| `FALSIFIED` 条目数 | **上升不是坏事** | 无期望值 |
| `DISPUTED` 条目数 | 应被及时处理 | 下降 |
| 未决争议时长 | 平均/最大 | 下降 |
| 阴性对照通过率 | **必须为 0** | **0%** |
| 回归数 | 基线从 PASS 变 FAIL | **0** |
| `UNVERIFIED` 事实核查项 | 待核查声明 | 下降 |

### 2.3 健康指标（本库特有的是"负面指标"）

**本库刻意展示下列"看起来不好"的指标**，因为它们反映验证在起作用：

- 被证伪条目数（上升 = 证伪机制在工作）
- 未通过验证的条目数
- 依赖缺失导致的 SKIP 数

**明确禁止**：为了"好看"而隐藏这些指标，或调整口径让数字好看。

## 三、告警规则

| 级别 | 触发条件 |
| --- | --- |
| 🔴 **致命** | 阴性对照通过（引擎失效）；`CANONICAL` 条目出现反例 |
| 🟠 **高** | 基线回归（PASS → FAIL）；伪造验证结果 |
| 🟡 **中** | 残差数量级漂移；新增长时间未决争议 |
| 🔵 **低** | SKIP 率上升；依赖版本过旧 |

## 六、诚实声明

看板**只展示可自动收集的指标**。下列重要维度**无法**自动化，需人工评估：

- 条目的数学重要性
- 证明的"优雅"程度
- 纲领的解释力

**我们不会给这些造一个数字。** 用数字衡量不可衡量的东西，是知识工程中最常见的自我欺骗。
