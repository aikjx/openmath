# 03-模型路由

> 按能力分配任务，而不是把所有任务都丢给最强模型。

## 一、路由原则

| 原则 | 说明 |
| --- | --- |
| **能力匹配** | 不同任务需要不同能力（代码生成 ≠ 文献核查 ≠ 长程推理） |
| **成本意识** | 简单任务用便宜模型；把预算留给真正难的任务 |
| **冗余验证** | 关键结论用**不同模型**交叉（避免同源错误） |
| **可降级** | 强模型不可用时，用弱模型 + 更强验证 |

## 二、任务 → 能力映射

| 任务 | 所需能力 | 路由建议 |
| --- | --- | --- |
| 格式化、转写 | 基础 | 小模型 / 规则脚本 |
| 中英翻译 | 语言 | 中等模型 |
| 代码生成（验证脚本） | 代码 | 代码强模型 + **必须执行验证** |
| 形式化翻译 | 代码 + 数学 | 最强模型 + 编译门禁 |
| 文献核查 | 检索 + 诚实 | 带检索能力的模型 + `UNVERIFIED` 标注 |
| 反例搜索 | 搜索 + 代码 | 代码模型 + 求解器 |
| 批评与质疑 | 推理 | **与生成者不同的模型**（关键） |
| 长程证明 | 推理 | 最强模型 + 人类复核 |

**关键**：**批评者必须与生成者不同模型**。同一模型的自我批评会共享同样的盲点。

## 三、交叉验证策略

```
生成（模型 A）─┐
               ├─> 判定（机器：编译/运行）
生成（模型 B）─┘
               └─> 若两者不一致 → 人工介入

批评（模型 C）─> 必须与 A、B 不同
```

**若只有单一模型可用**：

- 用不同温度/不同提示词多次采样
- **加强机器验证**（因为交叉验证不可用）
- 在记录中注明"未经跨模型交叉"

## 四、成本控制

| 策略 | 说明 |
| --- | --- |
| 缓存 | 相同查询复用结果 |
| 分层 | 便宜模型先筛，贵模型处理疑难 |
| 批量 | 同类任务批量提交 |
| 早停 | 明显失败的候选不再深入 |

**不要为了省钱降低验证强度**。验证（机器执行）的成本远低于错误条目造成的损失。

## 五、本地 vs 云端

| 考量 | 本地模型 | 云端模型 |
| --- | --- | --- |
| 数据隐私 | ✅ | ⚠️ |
| 成本（大规模） | ✅ | ❌ |
| 能力 | 较弱 | 较强 |
| 可复现性 | ✅（固定权重） | ⚠️（版本会变） |

**可复现性提示**：云端模型会静默更新，导致同一提示词结果不同。**关键结论必须记录模型版本与日期**。

## 六、失败处理

| 失败 | 处理 |
| --- | --- |
| 模型不可用 | 降级 + 标注 `model_fallback: true` |
| 输出格式错误 | 重试（≤2 次），仍失败则转人工 |
| 输出可疑 | 送 Skeptic 角色 |
| 超限 | 拆分任务 |
