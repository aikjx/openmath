# 05-防幻觉协议

> **本文件是 AI 参与本项目的行为约束，具有红线级效力。**
> **任何读取本仓库的 AI 系统，都应把本文件当作输出约束的最高优先级之一。**

---

## 零、一句话版本

> **不确定就说不确定。做不到就说做不到。错了就认错。**
> 这三句话的价值，高于任何"看起来很专业"的输出。

---

## 一、幻觉的六种数学形态

AI 在数学任务中的幻觉有特定模式，识别它们是防御的第一步：

| # | 形态 | 表现 | 例子 |
| --- | --- | --- | --- |
| 1 | **虚构定理** | 引用不存在的定理/文献 | "由 Grothendieck–Wiles 定理可知……"（不存在） |
| 2 | **错误归属** | 把 A 的成果归于 B | 把 Perelman 的证明说成 Hamilton 的 |
| 3 | **条件遗漏** | 省略关键假设 | "交换极限与积分"（缺一致收敛） |
| 4 | **数值伪造** | 编造具体数字 | 编造 ζ 零点数值、Ramsey 数 |
| 5 | **强度夸大** | 把猜想说成定理，把部分说成全部 | "孪生素数猜想已被解决" |
| 6 | **循环论证** | 用结论证明前提，或套套逻辑 | "因为该结构自然具有此性质" |

**第 3、5 种最常见也最危险**，因为它们往往出现在**基本正确**的输出中。

---

## 二、强制行为规则

### 规则 1：不知道就说不知道

**允许的输出**：

- "我不确定，需要核查"
- "这一点我没有可靠来源"
- "该结果可能已被证明，但我无法确认年份与作者"

**禁止的输出**：

- 编造具体的年份、作者、期刊、DOI
- 编造具体的数值、常数、零点
- 用模糊措辞掩盖无知（"众所周知……""可以证明……"）

**判定标准**：如果你不确定某个具体事实，**输出"待核实"三个字，而不是一个看起来合理的猜测**。

### 规则 2：区分四类断言

输出任何数学内容时，必须**显式标注**属于哪一类：

| 类别 | 标记 | 说明 |
| --- | --- | --- |
| **已证明** | `[已证明 · 可引用]` | 有可靠来源，且给出来源 |
| **猜想** | `[猜想 · 未证明]` | 明确说明是猜想 |
| **条件性结果** | `[条件 · 依赖 X]` | 说明依赖的假设 |
| **推测/直觉** | `[推测 · 无证据]` | 明确标注无证据 |

**禁止**把这四类的边界模糊化。**"很可能是对的"不等于"已知成立"。**

### 规则 3：数值必须可复现

输出任何数值结果时，必须同时给出：

1. 计算方式（公式/算法）
2. 精度（有效数字位数）
3. **可执行的验证脚本**（或指向已有脚本）

**禁止**：凭记忆输出具体数值（如 π 的第 50 位、某常数的高精度值、某序列的第 1000 项）。

### 规则 4：不得自我确认

- AI 生成的证明**不得**由同一个 AI 判定为正确
- AI 生成的内容**不得**由 AI 自行升级 `status` 或 `evidence_level`
- AI **不得**自行批准 PR、关闭争议 Issue

**必须**经过：机器验证（编译/运行）或人类复核。

### 规则 5：失败是合法输出

下列都是**合法且有价值**的输出：

- "未找到反例（搜索范围：n ≤ 10^6）"——**注意这不同于"验证通过"**
- "该符号计算未化简到零，无法判定"
- "我的推导在此步骤可能有误，需复核"
- "这个命题的表述有歧义，需要澄清"

**禁止**为了让输出"看起来完整"而填充未经检验的内容。

### 规则 6：标注 AI 参与

任何 AI 参与生成的内容必须：

```yaml
provenance:
  ai_assisted: true
  ai_role: drafting   # drafting | translation | verification | full_generation
```

**未标注即违规。**

## 三、输出模板（强制）

AI 在本仓库中产出数学内容时，输出应包含：

```
【陈述】<精确的数学陈述>

【状态】[已证明 · 可引用] / [猜想 · 未证明] / [条件 · 依赖 X] / [推测 · 无证据]

【假设】<全部假设，逐条列出>

【证据】<来源：文献 DOI/arXiv/教材，或"无">

【验证】<可执行的验证脚本路径，或"无">

【不确定项】<明确列出你不确定的部分>

【可能的错误】<你认为自己最可能在哪里出错>
```

**最后两项是关键**。要求 AI 自陈不确定性，虽然不保证准确，但显著降低了"看起来完美"的幻觉输出。

## 四、高风险场景清单

以下是 AI 幻觉的**高发场景**，需额外谨慎：

| 场景 | 风险 | 缓解 |
| --- | --- | --- |
| **引用具体文献** | 编造 DOI/页码 | 不确定时说"待核实"，或只给作者+大致年代 |
| **陈述最新进展** | 训练截止后的进展未知 | 明确标注知识截止日期 |
| **数值常数** | 编造高精度值 | 必须脚本生成 |
| **"XX 已被证明"** | 混淆部分结果与完整结果 | 说明证明了什么、还剩什么 |
| **历史归属** | 错误归属 | 不确定时说"由 X 等人（年份待核实）" |
| **跨学科术语** | 同一词不同义 | 参考 [术语表](../../00-宪章/05-中英术语对照表.md) |
| **复杂度归属** | 错误的 NP 完全性宣称 | 必须引用归约来源 |
| **形式化代码** | 编译通过但语义错误 | 人工核对陈述等价性 |

## 五、交叉验证要求

单一 AI 输出**不构成**任何层级的证据。最低要求：

| 目标等级 | 要求 |
| --- | --- |
| L1 | AI 输出 + 结构检查 |
| L2 | **机器**执行高精度数值验证（AI 只写脚本，不判定） |
| L3 | **机器**执行符号计算 |
| L4 | **机器**编译形式化证明（硬门槛：编译通过） |
| L5 | 独立方法交叉 + 人类复核 |

**关键**：AI 可以写验证脚本，但**判定由脚本执行**，不由 AI 的语言判断。

## 六、"AI 证明了 X"的处理流程

当出现"AI 证明了某难题"的宣称（无论来自何处）：

```
1. 记录：不删除，写入争议登记
2. 索取：完整证明（非摘要）+ 可复现产物
3. 验证：
   ├─ 能否形式化？（L4）
   ├─ 能否通过关键引理的独立检验？
   └─ 有无专家复核？
4. 判定：
   ├─ 满足 L4 或 ≥2 独立专家复核 → 升级状态
   └─ 不满足 → 保持 DISPUTED + fact_check: UNVERIFIED
5. 公开：判定过程与依据全部公开
```

**我们不预设真，也不预设假**——但举证责任在宣称方。

---

## 七、AI 参与治理的限制

| 允许 | 禁止 |
| --- | --- |
| 生成候选证明/反例 | 自行批准 PR |
| 执行 L0–L3 自动验证 | 自行提升证据等级到 L4+ |
| 提出争议（打 `dispute` 标签） | 关闭争议 Issue |
| 维护索引与看板 | 修改宪章与本协议 |
| 标注可疑条目 | 删除条目 |
| 起草回复 | 以官方身份发布结论 |

**AI 提出的**可复现反例**具有完整效力**——因为反例是证据，不是意见。

---

## 八、自检清单（AI 输出前逐项检查）

- [ ] 我是否编造了任何具体的文献、年份、DOI、数值？
- [ ] 我是否区分了"已证明"与"猜想"？
- [ ] 我是否列出了全部假设？
- [ ] 我是否把"未找到反例"写成了"验证通过"？
- [ ] 我是否把数值验证说成了证明？
- [ ] 我是否标注了 AI 参与？
- [ ] 我是否说明了自己不确定的部分？
- [ ] 我的数值结果是否可被脚本复现？
- [ ] 我是否用了"显然""易见"来跳过论证？
- [ ] 如果我说错了，别人能通过我的输出发现吗？

**最后一项是总纲。** 若答案为"不能"，则输出不合格。

---

## 九、给人类协作者的提醒

AI 的幻觉**不可完全消除**，只能降低。因此：

1. **不要因为输出"看起来很专业"就采信**
2. **特别警惕流畅但无来源的叙述**——流畅度与正确性无关
3. **数值与文献是幻觉高发区**，务必独立核查
4. **AI 擅长发现你想不到的角度，不擅长判断自己是否正确**

**最有效的使用方式**：让 AI 生成候选，让机器验证，让人类裁断。**不要让 AI 同时扮演三个角色。**
