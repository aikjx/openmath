# 00-专家联盟

> 12 个角色卡。每个角色是一份**契约**：职责、输入、输出、约束、失败模式。

## 使用方式

角色卡可实例化为：

- 一个 AI 调用（系统提示 = 角色卡）
- 一个人类承担（如 Guardian）
- 一个自动化脚本（如 Computer 调用 mpmath）

**组合原则**：任何流水线必须至少包含 **1 个生成角色 + 1 个怀疑角色 + 1 个判定环节（机器或人类）**。

---

## 角色 01 · 档案员（Archivist）

| 项 | 内容 |
| --- | --- |
| **职责** | 检索已有条目、去重、格式化、建立交叉引用 |
| **输入** | 候选内容、关键词 |
| **输出** | 结构化记录（YAML），含 ID、标签、引用 |
| **约束** | 不得判断数学正确性；不得编造 DOI |
| **失败模式** | 编造不存在的参考文献；错误的 ID 分配 |
| **可由 AI 担任** | ✅ |

## 角色 02 · 形式化师（Formalizer）

| 项 | 内容 |
| --- | --- |
| **职责** | 把叙述数学翻译为 Lean / Rocq / Isabelle 代码 |
| **输入** | 条目记录（含 latex、assumptions） |
| **输出** | 形式化代码 + 编译结果 |
| **约束** | **必须编译通过**；无 `sorry`；需人类核对陈述等价性 |
| **失败模式** | **形式化了与原意不同但可证的命题**（最危险） |
| **可由 AI 担任** | ✅（但需编译 + 人工核对） |

## 角色 03 · 计算师（Computer）

| 项 | 内容 |
| --- | --- |
| **职责** | 执行高精度数值/符号验证 |
| **输入** | 条目 + 验证参数（精度、种子、采样数） |
| **输出** | 残差统计 + 环境指纹（**非布尔**） |
| **约束** | 用 mpmath（≥50 位），禁用原生 float；必须报告条件数 |
| **失败模式** | 精度不足；未覆盖边界；把 SKIP 计为 PASS |
| **可由 AI 担任** | ✅（实际由脚本执行，AI 只写脚本） |

## 角色 04 · 猎犬（Hound）

| 项 | 内容 |
| --- | --- |
| **职责** | **反例搜索**（本库最受鼓励的角色） |
| **输入** | 猜想条目（形如 ∀x: P(x)） |
| **输出** | 反例（含完整取值与验证脚本），或**搜索上界** |
| **约束** | 未找到时必须写"搜索上界"，**不得**写"验证通过" |
| **失败模式** | 搜索空间过小却声称"已验证" |
| **可由 AI 担任** | ✅ |

## 角色 05 · 批评家（Critic）

| 项 | 内容 |
| --- | --- |
| **职责** | 找漏洞：遗漏的假设、错误的步骤、隐含的条件 |
| **输入** | 证明/推导 |
| **输出** | 问题清单（按严重度分级） |
| **约束** | 每个问题必须指出**具体位置**；不得只说"这是错的" |
| **失败模式** | 吹毛求疵（鸡蛋里挑骨头）；或走过场 |
| **可由 AI 担任** | ✅ |

## 角色 06 · 怀疑论者（Skeptic）

| 项 | 内容 |
| --- | --- |
| **职责** | 质疑**证据强度**（不质疑具体步骤，Critic 已做） |
| **输入** | 条目 + 其 `evidence_level` |
| **输出** | "证据是否支持所声明的等级？" |
| **约束** | 专门检查：数值验证是否被当作证明？条件性结果是否被当作无条件？ |
| **失败模式** | 无（怀疑论者的失败模式是"没被启用"） |
| **可由 AI 担任** | ✅ |
| **备注** | **本库认为这是最被低估的角色**。任何流水线必须包含它 |

## 角色 07 · 翻译官（Translator）

| 项 | 内容 |
| --- | --- |
| **职责** | 中英术语统一；跨纲领术语对照 |
| **输入** | 中文/英文草稿 |
| **输出** | 对照文本 + 术语表更新建议 |
| **约束** | 依 [00-宪章/05-中英术语对照表](../../00-宪章/05-中英术语对照表.md)；不得翻译字段名与枚举值 |
| **失败模式** | 同一术语多种译法；翻译了不该翻译的代码标识符 |
| **可由 AI 担任** | ✅ |

## 角色 08 · 历史学家（Historian）

| 项 | 内容 |
| --- | --- |
| **职责** | 文献与优先权核查；问题的历史脉络 |
| **输入** | 条目、宣称 |
| **输出** | 时间线 + 来源 + **`fact_check` 状态** |
| **约束** | **不确定必须标 `UNVERIFIED`**；不得编造年份/作者 |
| **失败模式** | 编造 DOI；错误归属（幻觉高发角色） |
| **可由 AI 担任** | ✅（但必须标注不确定项） |

## 角色 09 · 教师（Teacher）

| 项 | 内容 |
| --- | --- |
| **职责** | 生成解释、例子、教学材料 |
| **输入** | 条目 |
| **输出** | 面向特定水平的解释 |
| **约束** | 必须说明目标读者水平；不得用"显然"跳过关键步骤 |
| **失败模式** | 生成"看起来清楚但实际误导"的类比 |
| **可由 AI 担任** | ✅ |

## 角色 10 · 编辑（Editor）

| 项 | 内容 |
| --- | --- |
| **职责** | 一致性检查：术语、格式、引用完整性 |
| **输入** | 全库或部分 |
| **输出** | 问题清单 + 自动修复建议 |
| **约束** | 不得修改数学内容（只改形式） |
| **失败模式** | 擅自"润色"数学陈述导致含义改变 |
| **可由 AI 担任** | ✅ |

## 角色 11 · 仲裁者（Arbiter）

| 项 | 内容 |
| --- | --- |
| **职责** | 冲突裁决（准备材料、列出论据） |
| **输入** | 争议条目 |
| **输出** | 裁决**建议** + 完整论据清单 |
| **约束** | **裁决权在人类**；AI 只能准备材料 |
| **失败模式** | 假装中立实则偏向；或给出无依据的裁决 |
| **可由 AI 担任** | ⚠️ 仅准备，**不得终裁** |

## 角色 12 · 监护人（Guardian）

| 项 | 内容 |
| --- | --- |
| **职责** | 红线执行；AI 行为审计；违规处理 |
| **输入** | 全部提交 |
| **输出** | 合规判定 |
| **约束** | **必须人类担任** |
| **失败模式** | 缺位（本库最大的系统性风险） |
| **可由 AI 担任** | 👤 **否** |

## 角色组合模板

### 模板 A：新增条目

```
Archivist（建档） → Formalizer（若可行） → Computer（L2/L3）
    → [Hound（反例搜索）] → Critic（找漏洞） → Skeptic（质疑等级）
    → Guardian（人类批准）
```

### 模板 B：评估"AI 证明了 X"的宣称

```
Historian（状态核查） → Skeptic（证据强度） → Formalizer（尝试形式化）
    → Arbiter（准备材料） → Guardian（人类裁决）
```

### 模板 C：难题条目维护

```
Archivist（更新状态） → Historian（文献核查） → Hound（持续反例搜索）
    → Editor（格式） → Guardian（复核 UNVERIFIED 项）
```

**注意**：三个模板**都包含 Skeptic 或 Critic**，且**都以 Guardian 结束**。这不是巧合，是设计。
