# 06-AI自动化

> **"你是数学专家联盟"** —— 本目录把这句话**工程化**为一组可执行的角色、流程与协议。

## 一、核心理念

大语言模型在数学上的真实能力是**不对称**的：

| 强 | 弱 |
| --- | --- |
| 文献检索与归纳 | 长链严格推理 |
| 提出候选思路 | 发现自己推理中的错误 |
| 形式化翻译（部分） | 判断命题是否已被证明 |
| 生成候选反例 | 评估证据强度 |
| 格式化与转写 | 承认不知道 |

**核心设计原则**：

> **AI 负责生成与搜索，机器（而非 AI）负责判定，人类负责裁断。**

这个三方分工是本目录全部设计的基石。**绝不让 AI 自己给自己的输出打分**——这是自评分幻觉的根源。

## 二、"专家联盟"是什么

不是一个模型，而是一组**角色卡**（persona + 职责 + 约束 + 输出契约），可实例化为：

- 同一个模型的多次调用（不同系统提示）
- 不同模型的组合（按能力路由）
- 人机混合（某些角色由人类担任）

**角色一览**（详见 [00-专家联盟](00-专家联盟/README.md)）：

| # | 角色 | 职责 | 可否由 AI 担任 |
| --- | --- | --- | --- |
| 1 | 档案员 Archivist | 检索、去重、格式化 | ✅ |
| 2 | 形式化师 Formalizer | 叙述 → Lean/Coq | ✅（需编译验证） |
| 3 | 计算师 Computer | 高精度数值/符号验证 | ✅（引擎执行） |
| 4 | 猎犬 Hound | **反例搜索** | ✅ |
| 5 | 批评家 Critic | 找漏洞、检查假设 | ✅ |
| 6 | 怀疑论者 Skeptic | 质疑证据强度 | ✅ |
| 7 | 翻译官 Translator | 中英术语统一 | ✅ |
| 8 | 历史学家 Historian | 文献与优先权核查 | ✅ |
| 9 | 教师 Teacher | 生成解释与教学材料 | ✅ |
| 10 | 编辑 Editor | 一致性与规范检查 | ✅ |
| 11 | **仲裁者 Arbiter** | 冲突裁决 | ⚠️ 仅记录，**最终裁决权在人类** |
| 12 | **监护人 Guardian** | 红线执行、AI 行为审计 | 👤 **必须人类** |

**关键**：第 11、12 号角色**不能由 AI 独立担任**。AI 可以准备材料，但裁决与审计必须有人类签名。

## 四、五条铁律

1. **AI 不得自评**：AI 生成的证明不得由同一个 AI 判定通过
2. **机器判定优先**：能编译/能跑的验证，优先于模型自述
3. **输出必须可复现**：每个结论必须附带可执行的验证脚本
4. **怀疑论者必选**：任何流水线都必须包含 Critic 与 Skeptic 环节
5. **人类保留否决权**：任何环节的人类否决都是终局的

## 五、AI 自动化的能力边界（诚实）

由 [01-数学体系/15-离散数学与理论计算机](../01-数学体系/15-离散数学与理论计算机/README.md) 提供的理论依据：

| 边界 | 理论依据 | 后果 |
| --- | --- | --- |
| 自动定理证明不可能完备 | 不可判定性、哥德尔不完备 | 必须人机协作 |
| 反例搜索规模受限 | NP 完全性 | 小参数有效，大规模受限 |
| 概率可检验证明可行 | PCP 定理 | 可用交互方式高效验证 |
| "AI 证明"可被高效检验 | 交互式证明理论 | **让 AI 生成，让机器验证** |

**最后一条是本库的架构基础**：我们不要求 AI 输出"正确的证明"，我们要求 AI 输出**可被机器高效检验的候选**。
