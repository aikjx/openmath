# 04-人类在环

> **哪些环节必须有人类？如何让人类介入的成本最低？**

## 一、为什么必须有环

纯自动化的数学研究**不可能**成立，理由不是技术不足，而是原理性的：

| 障碍 | 来源 |
| --- | --- |
| 不可判定性 | 停机问题、哥德尔不完备 |
| NP 完全性 | 反例搜索的规模限制 |
| 语义判定 | "形式化是否正确表达了原意"不可由机器完全判定 |
| 价值判断 | "这个问题重要吗"不是计算问题 |

因此本库的架构是 **AI 生成 + 机器验证 + 人类裁断**，人类是**不可替代的一环**。

## 二、必须人类介入的环节

| 环节 | 为什么 | 可否批量 |
| --- | --- | --- |
| **L4 形式化的陈述等价性核对** | 机器无法判断"形式化是否表达了原意" | 否 |
| **L5 专家复核** | 需要领域判断 | 否 |
| **争议裁决** | 需要裁断权 | 否 |
| **红线执行（Guardian）** | 需要责任主体 | 否 |
| **宪章修改** | 治理 | 否 |
| **条目重要性判断** | 价值判断 | 部分 |
| **L2/L3 失败后的定性** | 判断"这是真反例还是引擎问题" | 部分 |

## 三、人类介入的成本优化

人类时间是本库最稀缺的资源。优化策略：

### 1. 只让人做判断，不做搜索

- ❌ "请检查这 500 条条目"
- ✅ "这 3 条被机器标记为可疑，请判断"

### 2. 提供完整上下文

人类复核界面应一次给出：

- 条目内容
- 全部验证结果（含残差）
- 机器标记的疑点
- 相关条目链接

**不要**让人自己去翻仓库。

### 3. 分级处理

| 风险 | 处理 |
| --- | --- |
| 低（格式问题） | 自动修复 + 事后抽查 |
| 中（L2/L3 边界） | 人工快速确认 |
| 高（FALSIFIED、DISPUTED、L4、L5） | 人工深度介入 |

### 4. 异步与批量

- 人工复核不需要实时
- 可批量处理同类问题
- 结果写回仓库，可追溯

## 四、人类角色的职责边界

| 角色 | 职责 | 不负责 |
| --- | --- | --- |
| **评审者** | 审查证据与等级匹配 | 不需要重复全部计算 |
| **Guardian** | 红线执行 | 不需要判断数学正确性 |
| **形式化组** | L4 审核 | 不需要审查所有条目 |
| **治理组** | 争议与宪章 | 不介入技术细节 |

**重要**：人类也不应被要求做机器能做的事。人类复核一个数值结果时，**应该看脚本的残差报告，而不是自己重算**。

## 五、人类也会出错

本库同样承认人类的失误：

| 人类失误 | 缓解 |
| --- | --- |
| 过度信任 AI 的流畅输出 | 强制要求机器验证 |
| 锚定效应（先看结论再看证明） | 鼓励先看验证结果 |
| 疲劳导致的漏检 | 限制单次复核量 |
| 权威偏见 | 回避规则 + 匿名评审选项 |

**因此 [防幻觉协议](05-防幻觉协议.md) 中的部分条款同样适用于人类协作者**——特别是"区分已证明与猜想""不夸大强度"。

## 六、AI 辅助人类（反向）

人类也可以被 AI 辅助：

- 快速检索相关文献
- 生成复核算例
- 检查格式一致性
- 提示"你可能遗漏了 XX 假设"

**但要警惕**：AI 给人类提供的"检查清单"本身也可能有误。**AI 辅助人类 ≠ AI 替代人类判断**。
