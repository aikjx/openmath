## 一、这个项目是什么

OpenMath 不是一个公式速查表，也不是又一个教程站。它是一个**把数学知识当作可验证工程制品来管理**的开源研究库：

| 维度 | 传统做法 | OpenMath 做法 |
| --- | --- | --- |
| 知识单元 | 散落在 PDF / 网页中的叙述 | **原子知识单元（AKU）**：一条定义/公式/定理/猜想 = 一个带 ID 的机器可读记录 |
| 正确性 | 依赖读者与同行评审 | **分级证据链 L0–L6**，从格式校验到形式化证明逐层加码 |
| 数值验证 | 一次性的脚本 | **常驻回归基线**，任何修改都要重跑历史断言 |
| AI 的角色 | 生成文本 | **专家联盟流水线**：生成 → 证伪 → 形式化 → 人类复核，全程留痕 |
| 扩展性 | 目录写死 | **插件化验证中心**：任何人可注册新引擎、新层级、新分支 |

三句话概括：

1. **一切内容都可编号、可引用、可机器解析**（`OM-F-NT-0001` 这样的稳定标识）。
2. **一切断言都必须声明证据等级**，数值验证永远不能冒充证明（见 [诚实红线](00-宪章/02-诚实红线.md)）。
3. **一切结构都能无限扩展**：新分支、新纲领、新引擎都走同一套模板与门禁。

## 二、为什么要做（诚实的问题陈述）

- 数学文献正在**爆炸但不可检索**：arXiv 每年数万篇，人类无法逐一复核，AI 也无法在无结构文本上可靠推理。
- **AI 会编造证明**。这不是模型的偶发缺陷，而是概率生成的内在属性。因此社区必须提供**证伪优先**的基础设施，而不是让每个使用者各自踩坑。
- **形式化证明（Lean / Rocq / Isabelle）正在成为新的黄金标准**，但门槛极高。OpenMath 的目标是把"从叙述到形式化"的中间地带（符号验证、高精度数值、反例搜索）工程化，让形式化的成本降到可承受。
- 数学的**统一纲领**（范畴论、HoTT、Langlands、镜像对称……）各自为政，缺少一张可比较的评估矩阵。本库用同一套指标横向打分，并**强制标注不可通约之处**。

**我们不承诺**：不承诺"彻底解决统一场论"，不承诺 AI 自动发现定理，不承诺任何未经验证的结论。

## 三、目录地图

```
openmath/
├── 00-宪章/            不可协商的规则：红线、证据等级、编号、术语、治理
├── 01-数学体系/        全部数学分支（按 MSC2020 映射），每个分支一个知识域
├── 02-公式库/          原子化的公式记录（机器可读 + 人类可读双栏）
├── 03-难题与猜想/      未解 / 已解 / 已证伪难题的完整档案与状态机
├── 04-数学统一场论/    用不同体系假设研究"数学的统一"，含跨纲领翻译表与评估矩阵
├── 05-验证中心/        ★ 核心：L0–L6 分级验证、引擎插件、基线回归、看板
├── 06-AI自动化/        专家联盟角色卡、研究流水线、提示词库、防幻觉协议
├── 07-社区/            默认中文的全球化社区：入门、角色晋升、工作组、翻译
├── 08-工具/            openmath CLI（纯标准库可运行，可选依赖增强）
├── 09-数据/            数学常数、整数序列桥接、反例数据集
├── 10-文献与索引/      参考文献、知识图谱、交叉引用索引
├── 11-教育/            从科普到研究生：路线图与开放课程
├── 12-归档/            废弃纲领、历史版本（永不删除，只归档）
└── 99-沙箱/            自由探索区，不进质量门禁
```

每个目录都有 `README.md` 说明**它解决什么问题、放什么、不放什么、如何扩展**。

## 四、快速开始

```bash
# 1) 安装（核心功能零第三方依赖）
pip install -e .

# 2) 体检：检查环境与依赖能力
python -m openmath doctor

# 3) L0 校验：所有记录是否符合 schema、ID 是否唯一、引用是否可解析
python -m openmath lint

# 4) L2/L3 验证：数值 + 符号（需 sympy / mpmath，缺失时自动跳过并标记为 SKIP）
python -m openmath verify --level L2
python -m openmath verify --level L3

# 5) 生成看板与索引
python -m openmath status
python -m openmath index
```

Windows 用户可直接双击 [`启动脚本/一键验证.bat`](启动脚本/一键验证.bat)。

> **重要**：`verify` 输出 `PASS` **仅表示该层级未发现反例**。
> 只有 L4（形式化证明）通过才能使用"已证明"字样。详见 [证据等级标准](00-宪章/03-证据等级标准.md)。

## 五、一条记录的生命周期

```
DRAFT ──> PROPOSED ──> UNDER_REVIEW ──> VERIFIED(Lx) ──> CONSENSUS ──> CANONICAL
              │              │                │
              │              │                └──> DISPUTED（存在争议证据）
              │              └──> FALSIFIED（出现反例，条目永久保留并标注）
              └──> UNDECIDABLE（已知独立于公理系统，如连续统假设）
                    CONDITIONAL（依赖未证明假设，如"在 GRH 成立下"）
```

反例一旦出现，**禁止通过修改定义绕过**，必须新建记录并保留原条目的 `FALSIFIED` 状态。这是本库最重要的一条工程纪律。

## 六、贡献方式（30 秒版）

1. 复制对应目录下的 `_模板/`，按模板填写。
2. 跑 `python -m openmath lint` 直到零错误。
3. 提交 PR，标题用 `[域代码] 简述`，例如 `[NT] 新增 Riemann-von Mangoldt 公式`。
4. CI 会自动跑 L0–L3；L4 及以上需要至少一名人类复核者批准。

完整流程见 [CONTRIBUTING.md](CONTRIBUTING.md)。新手请从 [07-社区/00-入门](07-社区/00-入门/README.md) 开始。

## 八、现状与诚实边界

本库当前处于 **v0.1.0 骨架阶段**：目录结构、宪章、验证协议、工具链已就位；**内容覆盖远未完整**——数学体系的 17 个分支只有结构，公式库与难题档案已有 15 条记录（含 PWCV 素数离散框架 10 条）。

已可运行的实证（2026-09-10 实跑）：

```
openmath lint                 15 条记录，0 错误（L0 通过）
openmath verify --level L2    15/15 通过（ζ 函数方程最大残差 1.1e-50；PWCV 离散定理精确整数核对残差恒为 0）
openmath verify --level L3    2 条解析条目通过，3 条离散条目 SKIP（诚实标注）
openmath index                15 条，0 悬空引用
08-工具/tests/test_core.py    7/7 通过
prime_pi_block.py 自检        6/6 通过（精确素数计数四路交叉）
pwcv_theorems.py 自检        10/10 通过（PWCV 框架定理精确整数核对）
```

**`L4 = 0`**：本库目前**没有任何条目**可以被称为"已证明"。这不是缺陷，是诚实披露——L0–L3 只能筛掉错误，只有形式化才能确认真理。

我们不掩饰这一点。**骨架的价值在于它决定了后面十万个条目能否被正确地组织与验证。**

任何"完整""权威""终极"的表述都与本项目精神相悖。我们只承诺：**每一条被收录的内容，都能说清它的证据从哪里来、到哪一级为止。**
