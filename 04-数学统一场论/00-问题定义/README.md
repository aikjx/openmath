# 00-问题定义

> 在评估任何统一纲领之前，必须先说清"统一"指什么。
> 本节把 [README](../README.md) 中给出的四个维度**操作化**为可测量的指标。

## 一、为什么"统一"是个危险的词

"统一"在数学文献中至少有以下六种不同的用法，混淆它们会导致无效争论：

| 用法 | 例子 | 实质 |
| --- | --- | --- |
| **统一 = 共同推广** | 群统一了各种具体的对称群 | 找到一个更一般的概念 |
| **统一 = 共同基础** | 集合论统一了数学 | 找到共同的语言/公理 |
| **统一 = 建立字典** | Langlands 纲领 | 两个领域的对象一一对应 |
| **统一 = 简化证明** | 用范畴论简化同调代数 | 方法上的简化 |
| **统一 = 心理满足** | "这下一切都清楚了" | 主观体验 |
| **统一 = 修辞** | 论文标题中的"unified approach" | 无实质内容 |

**本库只承认前四种为有效含义，第五种不收录，第六种应当被批评。**

**检测方法**：如果一个"统一"在去掉之后，任何一个定理的证明都没有变短、任何一个新定理都没有产生，那么它是修辞。

## 二、四维度的操作化定义

### 维度一：表达力（Expressivity）

**定义**：纲领能否表述目标范围内的全部数学命题。

**测量方式**：

| 指标 | 说明 |
| --- | --- |
| MSC 覆盖率 | 能表述的 MSC 两位类数 / 目标类总数 |
| 翻译保真度 | 翻译后命题是否需要额外的"补丁"概念 |
| 表述膨胀率 | 同一命题在本纲领中的表述长度 / 标准表述长度 |

**诚实提醒**：几乎所有纲领在表达力上都能达到接近 100%（因为可以硬编码），因此**单独的表达力几乎没有区分度**。这就是为什么还需要其他三个维度。

### 维度二：解释力（Explanatory Power）

**定义**：纲领是否使既有结果变得更自然。

**测量方式**：

| 指标 | 说明 |
| --- | --- |
| 证明长度缩减比 | 用纲领重述后，典型证明的长度变化 |
| 概念的必要性 | 纲领中的概念是否"必然出现"，还是可任意替换 |
| 消除例外 | 是否消除了原本分散的特例处理 |

**好例子**：Erlangen 纲领把欧氏/仿射/射影/双曲几何统一为"不同变换群的不变量"，消除了大量重复。
**坏例子**：把所有概念重命名后套入某框架，证明长度不变甚至变长。

### 维度三：生成力（Generative Power）

**定义**：纲领是否产出了原本不会提出的问题与定理。

**测量方式**：

| 指标 | 说明 |
| --- | --- |
| 纲领催生的定理数 | 需引用具体文献 |
| 催生的新领域 | 如镜像对称催生枚举镜像对称 |
| 预测的验证 | 纲领**预测**而后被证明的命题数 |

**这是最有区分度的维度**，因为它不可伪造：要么有，要么没有。

**关键区分**：

- **解释既有结果** = 事后统一（retrospective）
- **预测新结果** = 事前统一（prospective）

只有后者才是强证据。这也是为什么本库要求 [可证伪预测](../06-可证伪预测/README.md)。

### 维度四：可执行性（Mechanizability）

**定义**：纲领能否被机器检查。

**测量方式**：

| 指标 | 说明 |
| --- | --- |
| 已有形式化库规模 | 如 mathlib 的声明数 |
| 自动化比例 | 证明中可由 tactic 自动完成的部分 |
| 判定性 | 是否存在判定过程（哪怕不实用） |

**为什么这是 21 世纪必须加入的维度**：

在 1900 年代，"能否被机器检查"不是评估标准。在 2020 年代，它是**决定纲领生命力的关键**——因为数学正在规模化，人类审查能力已成瓶颈。

HoTT 的吸引力很大程度来自这一点：**它天生是可计算的**（立方类型论、cubical agda）。

## 三、"统一"的三个层次（深度）

| 层次 | 描述 | 例子 |
| --- | --- | --- |
| **记法统一** | 只是换了写法 | 把 A 记成 B |
| **结构统一** | 揭示了共同的结构 | 群论统一各种对称性 |
| **机制统一** | 揭示了共同的**生成机制** | Langlands 中 L-函数为何出现 |

**只有第三层是深刻的统一**，前两层是组织工作。

## 四、评估的操作流程

```
1. 声明目标范围（哪个 MSC 区域？全部数学？）
        │
2. 逐维度打分（0–5，必须给出证据，不能凭感觉）
        │
3. 申报抽象税（为此付出了什么代价）
        │
4. 给出可证伪预测（什么结果会让本纲领被放弃）
        │
5. 交叉验证：至少一名非本纲领的评审者复核
```

**拒绝接受**下列形式的评估：

- "这个纲领显然更优雅"
- "我觉得这个更自然"
- "大部分人都用这个"

## 五、常见的无效批评（也要避免）

本库同样反对对统一纲领的**廉价批评**：

| 无效批评 | 为什么无效 |
| --- | --- |
| "太抽象了" | 抽象本身不是缺点，需要指出**具体**损失了什么 |
| "没什么用" | 需区分"现在没用"与"结构上无用"；基础研究的时间尺度是几十年 |
| "这只是重新表述" | 需给出证明长度/生成力的对比数据 |
| "我不用它也能做数学" | 个人实践不构成对纲领的评估 |

**批评与辩护都需要证据，这是本库的一贯立场。**
